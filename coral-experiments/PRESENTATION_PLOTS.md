# Presentation plot presets

Canonical config for the paper/deck figures across every answering model.
Anyone touching these plots must preserve the method choices below.

## Regenerate

| cf2 pool (all 4 score/prob runs, incl. LSM) | `conda run -n coral python3 -m scripts.shared.plot_cf2_bfs_lsm` | `presentation_plots/<run>-cf2/` |

**Score/prob-elicited variants** (`plot_qwen3_scores_bfs_sra --run <run>`) run on the LLM-scored lattices under `coral-runs-lattices/<run>/`. Four runs share identical lattice inputs (same qids/atoms/plausible answers): `qwen3-32b-100` (the original run, renamed from `qwen3-32b`; 0–100 answer scores stored ÷100 under `"scores"`), `qwen3-32b-percentage`, `qwen35-122b-100`, and `qwen35-122b-percentage` (`-percentage` runs elicit answer probabilities under `"probs"`; `load_score_lattices` accepts either key). No ContextCite data exists for any of them, so the LSM lines are replaced by score-fed ERA variants: identical `mra_search` softmax config plus `scores_by_combo` with `voter_norm="max"`, labeled "ERA-scores (b=*)" in the LSM color slots. BFS/SRA/MRA rows are computed fresh (no `paper_results.json`) from `logged_results/qwen3-32b/<dataset>/cases.json` (shared across all four runs for comparability) and cached to `logged_results/<out_name>/<dataset>/results.json` — delete that file to recompute. `--run qwen3-32b-100` (the default) keeps its historical output name `qwen3-32b-scores`; the others use the run name. Only supports `--datasets`; combined grid is `bfs_sra_mra_combined.png`.

**cf2 pool** (`plot_cf2_bfs_lsm`, per-run flags `--runs`/`--datasets`): cases from `data/cases_16x20_cfmin3.json` (generated by `scripts.shared.generate_cf2_pool`: 20 sub-lattices per size k=3–9 whose **shallowest CF needs ≥3 removals for k≥4** (≥2 for k=3, where only depths 2–3 exist) — a floor, not a pin; depth beyond the floor is natural — plus the 16 base k=10 lattices, per run × dataset). This supersedes `cases_16x20_cf2removals.json`, which pinned depth to exactly 2; the LSM GPU results (`cc_results_budget_*`) were run on that old pool, so only rows whose case (qid + start node) is unchanged still apply — the seeded `cc_results_budget_*.json` keep exactly those (16 k=10 rows + a few coincidental re-samples per dataset); re-running CC fills in the rest (new rows record `start_node` for exact staleness checks). BFS/SRA/ERA rows come from `logged_results/<run>-cf2/<dataset>/results.json` (`scripts.shared.eval_cf2_bfs_sra_era` — same method conventions: native-combsum SRA, `mra_search` softmax b=4/8/16 labeled "ERA"; delete to recompute). LSM comes from `cc_results_budget_{4,8,16}.json` in the same dir (GPU step `run_cc_cf2_parallel.sh`); budgets with missing or partially-checkpointed files are skipped, so 32B plots have no LSM lines until those CC runs finish. Panel drawing is imported from `plot_qwen3_temp0_bfs_lsm`, so layout/colors/cost conventions stay identical. Because CF depth is controlled (~2), ERA accuracy is much higher here than on the uncontrolled subsample sweeps — don't compare across pools.

Sample-size caveats: prob-elicited rankings are far more stable, so many sub-lattices have no counterfactual and are skipped (e.g. msmarco_criteria drops from 152 to 71 cases between `qwen3-32b-100` and `qwen3-32b-percentage`). `qwen35-122b-percentage` additionally has 38 halted qids (incomplete lattices, mostly pragma datasets) that `load_score_lattices` skips because the full start combo is missing.

**70B variants have no MRA or LSM data yet** — only BFS + SRA + true ERA (b=4/8/16, precomputed in `paper_results.json`). The script auto-forces `--backend era` for these models and drops LSM from the legend, so their outputs live under `presentation_plots/true_era/` alongside the 8B/Qwen true-ERA plots.

Both scripts accept these flags:

- `--labels {era,mra}` (default `era`) — legend text only, same data underneath.
  - `era` → "ERA (b=*)" (paper convention), no filename suffix.
  - `mra` → "MRA (b=*)" (honest label), filename gets `_mra` suffix.
- `--backend {mra,era}` (default `mra`) — swaps the underlying algorithm.
  - `mra` (default) → `mra_search(normalize_fn="softmax")` — paper-facing choice.
  - `era` → real `era_search` from `search/rank.py`. Legend forced to "ERA", filename gets `_era` suffix. (Llama: reuses `era_b4`/`era_b8` from `paper_results.json`, computes `era_b16` on the fly. Qwen: computes all three via `era_search`.)
- `--datasets <name> [<name> ...]` — restrict to a subset (e.g. `--datasets msmarco_pragma`). When restricted, the 3×4 combined grid is skipped.
- `--merge` — pool `<family>_criteria` + `<family>_pragma` per family. Produces 2 plots (`msmarco.png`, `curated.png`) at the model root instead of 4 per-dataset plots. Meant for slides where four figures are too many. X-axis becomes "Number of Available Concepts". No combined grid is emitted.

Variants coexist in the output tree. `--backend era` writes to a separate `presentation_plots/true_era/<model>/` subtree (so paper-facing MRA figures never mix with the true-ERA sanity checks); the other variants share the `presentation_plots/<model>/` root and disambiguate by filename suffix.

| Command | Files (per-dataset mode) | Files (`--merge` mode) |
|---|---|---|
| default              | `<model>/<dataset>/<dataset>.png`, `<model>/bfs_lsm_mra_combined.png` | `<model>/msmarco.png`, `<model>/curated.png` |
| `--labels mra`       | `<model>/<dataset>/<dataset>_mra.png`, `<model>/bfs_lsm_mra_combined_mra.png` | `<model>/msmarco_mra.png`, `<model>/curated_mra.png` |
| `--backend era`      | `true_era/<model>/<dataset>/<dataset>.png`, `true_era/<model>/bfs_lsm_mra_combined.png` | `true_era/<model>/msmarco.png`, `true_era/<model>/curated.png` |

**All presentation-facing figures live under `presentation_plots/`** — kept separate from `plots/` (which holds exploratory/ablation figures) so the deck-ready outputs are easy to find and version.

Both emit one 3-panel figure per dataset + a 3×4 combined grid
(`bfs_lsm_mra_combined.png`, or `..._mra.png` under `--labels mra`).

Other models (`llama31-70b`, `llama33-70b`, `qwen3-32b` no-temp) currently
have only BFS + SRA results in `logged_results/<model>/` — no MRA sweeps,
no ContextCite runs. Add plot scripts for them only after those runs land.

## Methods (what each legend label really means)

Applies to **every** model plot. Never substitute alternate backends without
updating this file first.

| Legend | Backend | Where the values come from |
|---|---|---|
| **BFS**            | oracle ground truth | `paper_results.json` → `bfs` |
| **SRA**            | `sra_search(aggregator="combsum")` — **native hand-crafted Borda** (`search/rank.py:_combsum`). NOT pyflagr. | `paper_results.json` → `sra` |
| **ERA (b=4/8/16)** *(default)* or **MRA (b=4/8/16)** *(with `--labels mra`)* | `mra_search(normalize_fn="softmax", entropy_fn=shannon_entropy, concepts=start_node)` — the exact paper Table I config. Underlying algorithm is MRA either way; only the legend text changes. Computed on the fly per plot run so the config always matches Table I. | Both models: computed on the fly per run against `data/<model>/*-lattices.json`. |
| **LSM (b=4/8/16)** | ContextCite Lasso surrogate | `cc_results_budget_{4,8,16}.json` |

## Panels

Three panels per dataset, x-axis = k (number of criteria in the sub-lattice, 3..10).

| Panel | Y-axis | Formula (per method, per k) |
|---|---|---|
| Left  | Accuracy (%) | `100 × #{outcome=="correct"} / #cases`. Correct = proxy CF's ground-truth top-1 differs from baseline AND matches BFS's CF layer. BFS ≡ 100%. |
| Mid   | Avg Cost (LLM Calls) | BFS: `calls`. SRA / MRA ("ERA"): `calls + budget_used` (no preload adjustment — matches paper Table I convention). LSM: `calls + budget`. |
| Right | Distance to True Counterfactual | Mean `|proxy_layer − bfs_layer|` over cases where `outcome != "correct"` (correct cases excluded). Bars ± std. |

## Do not change without noting here

- The "ERA" label maps to `mra_search` results, not `era_search`. The paper convention is preserved.
- SRA is the native combsum path (`sra` column in `paper_results.json`), NOT the pyflagr Borda in `rank_agg_sra.json`. Native and pyflagr agree exactly on msmarco_criteria but drift 5-10% on the other three (tie-break differences cost pyflagr 1-2 pp of accuracy on pragma datasets).
- MRA is called with `concepts=start_node` in both plot scripts and in `run_mra_budget_ablation.py` — this is intentional; it scopes Phase-1 exploration to the sub-lattice. Do not "fix" to `concepts=full_criteria`.
- MRA entropy is `shannon_entropy` (the `mra_search` default), NOT `softmax_entropy`. This matters — the cached `mra_budget_ablation/results.json` files use `softmax_entropy` (via explicit override in `run_mra_budget_ablation.py:99`) and produce slightly different numbers. The plot scripts compute MRA fresh with `shannon_entropy` so they match paper Table I exactly.
- Cost formula is `calls + budget_used` for SRA and MRA — no preload adjustment (matches paper Table I). Earlier versions added `+k` / `+k+1` for "fairness" but this deviated from the paper's reported numbers.
- For datasets where the current lattice file has dropped/halted a qid, `_load` filters those cases out so plot sample sizes match paper Table I (e.g. `curated_pragma` on llama is `n=150`, not 156).
